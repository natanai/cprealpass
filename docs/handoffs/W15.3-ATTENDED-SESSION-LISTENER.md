## Goal

Implement the new canonical owner-facing attended-test lifecycle so that when the parent says a Biology build is **ready for PC testing**, the owner performs one action only: run one command or one thin `.cmd` launcher, wait for the quiet listener to report `READY TO LAUNCH CYBERPUNK`, launch/test/exit the game normally, then type `END` in the same window. The same session finalizes before/after evidence, asks the owner to confirm the handoff was sent, then removes its exact session-owned residue.

A `.cmd` launcher is explicitly allowed and preferred for owner ergonomics where useful. It must remain a thin launcher into the repository-owned PowerShell session engine; lifecycle logic must not be duplicated in batch.

## Required architecture

Create one reusable PowerShell session engine as the source of truth. The engine must be modular enough to support future integrated test plans and should separate:

1. exact-source/candidate preparation;
2. pre-launch baseline collectors;
3. quiet process/log listener;
4. post-exit collectors/comparators;
5. one evidence bundle finalizer;
6. confirmation-gated cleanup.

Do not create feature-specific pre/post command pairs as the new steady state.

## Owner interaction contract

The normal successful path must look like:

```text
<owner runs one command or .cmd>
...
READY TO LAUNCH CYBERPUNK
Listener active. Leave this window open.
After you have exited the game, return here and type END.

<owner launches/tests/exits game>
END
...
ATTACH THIS ONE EVIDENCE BUNDLE TO CHATGPT:
C:\Games\Biology-Operator-Evidence-<session-id>.zip
TYPE SENT AFTER THE FILE HAS BEEN ATTACHED
SENT
...
SESSION ENDED CLEANLY
```

The owner must not be asked to run a separate pre-launch probe, attach its report, wait, then run the game, then run a post-launch probe.

## Launch-failure requirement

If Cyberpunk never starts, starts and immediately exits, or otherwise fails during startup, the running listener must already capture the relevant bounded diagnostics as far as the current accepted architecture allows. It should include process observations plus relevant REDscript/configured-output/current-log and REDmod/package/task-runner state. The returned evidence must say what is known and what remains unknown; do not force a second manual diagnostic chain merely because launch failed.

## Evidence lifecycle

Reuse W15.2 managed evidence conventions where possible:

- one obvious handoff ZIP;
- machine-readable evidence + human-readable report;
- durable PASS/FAIL/partial outcome;
- exact source/candidate identity;
- zero-local-repo-safe bootstrap;
- temporary repo/worktree cleanup owned by the session;
- no human KEEP/delete list.

At `END`, finalize the handoff first. Do not delete the only local copy before the owner confirms it was successfully attached/sent. After confirmation, delete only exact session-owned temporary material and print a final clean-ended state.

The installed Biology candidate is not automatically disposable just because the session installed it. Removal/rollback of the candidate itself must remain an explicit ownership-safe test-plan decision.

## Documentation/CI cleanup

Align the active canonical docs and CI contracts with `docs/ATTENDED-TEST-SESSION.md`. In particular:

- `docs/LOCAL-OPERATOR-COMMANDS.md` must stop presenting multiple manual pre/post probes as the normal meaning of a ready-for-test handoff;
