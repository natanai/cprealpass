### Independently proven autonomous E3 activation regression

W20.3 compared recovered pre-autonomous source with rejected PR #153 rather than
treating #153 as trusted code.

The recovered/live-tested settings contract was:

```reds
CRRealpassSettings.IsEnabled(game)
  && (!IsDefined(settings) || settings.e3FirstPersonHudVisuals)
```

The rejected release changed that to require `settings` to already exist. Several HUD
adapters simultaneously changed from unconditional native-host frame creation to:

```reds
if enabled {
  this.CRCreateBiologyE3...();
}
```

This creates a concrete lifecycle failure:

```text
HUD controller initializes before CRRealpassSettings attaches
-> preference read becomes false
-> Biology presentation child is never created
-> later saved preference availability cannot show a child that does not exist
```

The rejected release also attempted a UISystem refresh event. W20.3 independently
checked public redscript UISystem consumers and found **mixed callback naming in working
mods**: for example, Limited HUD's simple toggle queues `ToggleHudEvent` and receives
`OnToggleHud`, while other established UISystem events use full Event-suffixed
callbacks such as `OnLHUDConfigUpdatedEvent` and
`OnInjectPocketGuideToHudEvent`.

W20.3 therefore does **not** claim that PR #153's Event-suffixed callback name was the
regression cause. The proven cause remains the early fail-closed settings read combined
with conditional/lazy frame creation.

For compatibility, each live E3 controller exposes both aliases:

```text
CRBiologyE3PreferenceChangedEvent
-> OnCRBiologyE3PreferenceChanged
-> OnCRBiologyE3PreferenceChangedEvent
```

Both aliases perform the same idempotent refresh and return false so the stateless
notification can continue propagating. The event carries no Boolean; every controller
re-reads the one persistent `CRRealpassSettings.e3FirstPersonHudVisuals` authority.

### Settings / presentation lifecycle repair

`RealpassSettings.reds` now:

- retains REDlauncher/REDmod activation as the whole-mod gate;
- retains the single save-persistent E3 Boolean;
- preserves default-ON behavior while the settings ScriptableSystem is not yet attached;
- emits a stateless UISystem refresh event when the saved Boolean actually changes;
- emits the same reconciliation event from `OnAttach` and `OnRestored`;
- treats setting OFF as a successful write rather than confusing `false` with failure.

Meaningful native-hosted frames are once again created independently of preference
value. Preference controls visibility/style, not whether the presentation tree is ever
allowed to exist.

The following controllers subscribe through both compatible callback aliases:

- lower-left healthbar host;
- D-pad/hotkey host;
- minimap/navigation host;
- interaction host;
- activity-log entry;
- ordinary crosshair;
- quest tracker;
- weapon roster;
- NPC nameplate controller.

### W20.2 preference placement preserved; T007 click repaired

The preference remains inside W17's authored/local Biology detail composition. It is not
moved back to a fullscreen root or TopRight coordinate.

The source-level T007 click defect was a brittle pointer ownership check:
the callback could reject the release when the event's current target was a decorative
child rather than the row.

W20.3 keeps the 680x48 row interactive, explicitly makes the label/value/background
children non-interactive, removes the `GetCurrentTarget() != row` rejection, writes
through `CRRealpassSettings`, refreshes the visible ON/OFF value immediately, and only
handles the pointer event after a successful saved-setting write.

If save settings authority is genuinely unavailable, the row says `UNAVAILABLE`
rather than displaying a false saved state.

### E3 OFF restoration repair

W20.3 strengthens OFF from "hide custom frame" to a reversible native lifecycle:

- quest title/objective tracking tints restore before native tracker updates, capture
  flags are released, then a later ON samples the current native style again;
- weapon/ammo tints follow the same restore -> native update -> recapture pattern;
- activity log restores/releases native tint on every pass and no longer mutates letter
  case because no native letter-case capture contract existed;
- ordinary crosshair restores/releases its native tint before native state transitions;
- nameplate text/frame tint, frame opacity/visibility and native range restore;
- nameplate font style/letter case are no longer mutated because they lacked a reversible
  native capture contract;
- scanner/preference ownership changes re-run native nameplate `SetVisualData` using
  the last unchanged native `NPCNextToTheCrosshair` payload so Biology fallback text
  cannot survive OFF.
