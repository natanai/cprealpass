# Local Cyberpunk Game Reference

## Purpose

Remote GitHub agents do not have direct filesystem access to the user's installed copy of Cyberpunk 2077. The repository therefore maintains **GitHub-safe derived metadata** about the real local game and can ask the user to run targeted read-only PowerShell probes when that evidence matters.

This is part of Biology's patch-resilience strategy: foundational integrations should be based on the actual supported game build and stable semantic contracts rather than assumptions copied from old guides, online script dumps, or unrelated mods.

The supported game root is currently:

```text
C:\Games\Steam\steamapps\common\Cyberpunk 2077
```

Repository/workspace paths are not stable. Do not assume or recreate `C:\Games\CyberpunkRealism`; use `docs/LOCAL-OPERATOR-COMMANDS.md` for repository discovery/bootstrap.

## Prefer the installed official REDmod script tree for script contracts

When the question is about a Cyberpunk script class, event, function, field, controller, lifecycle, inheritance relationship, or nearby implementation context, prefer the official REDmod decompiled script tree from the installed game whenever it contains the needed evidence:

```text
C:\Games\Steam\steamapps\common\Cyberpunk 2077\tools\redmod\scripts
```

This is the normal first-choice readable source for native script archaeology on the supported game version. It is direct evidence from the user's installed build, not a web mirror.

Examples of facts that should normally be established from this tree before searching online:

- whether a controller/class exists in the supported build;
- exact event/function names and nearby signatures;
- inheritance and controller ownership;
- native editable/private field names visible in the decompiled source;
- which script file owns a HUD/menu/gameplay lifecycle;
- whether an old Project E3 or community-mod seam still maps to the current game.

Use narrow searches and report only the relevant relative paths, symbol names, signatures, or short diagnostic excerpts. Do not commit or upload bulk decompiled Cyberpunk source.

For presentation work, `tools/Probe-PresentationNativeContracts.ps1` is the current focused example: it reads the installed REDmod script tree and reports current HUD/nameplate/minimap controller evidence without modifying the game.

## Exact compilation is the hard script-compatibility gate

Readable REDmod source evidence answers "what does the installed game expose?". It does not by itself prove that Biology's wrapper/additive source compiles against the supported build.

For that, use the repository-owned exact compile path against the installed:

```text
r6\cache\final.redscripts
```

`tools/Audit-GameContracts.ps1` and `tools/Build-BiologyPackage.ps1` use the supported local toolchain to compile Biology against the actual game script bundle without modifying the game cache.

A strong native-seam workflow is therefore:

1. inspect the installed REDmod `.script` source for the current class/lifecycle/field contract;
2. implement the smallest Biology-owned seam;
3. exact-compile against the installed `final.redscripts`;
4. perform attended runtime acceptance only after those static gates pass.

## Evidence priority

When a question is about what Cyberpunk itself contains, exposes, names, calls, stores, or does, use this order:

1. repository-owned code/tests and already-recorded `reference/cyberpunk/` evidence;
2. the installed official REDmod decompiled script tree for readable script contracts;
3. exact compile or another narrow direct probe against the user's installed game;
4. official CDPR/REDmod/framework/tool documentation and release notes;
5. web/community script dumps, guides, and examples only as secondary context.

Do not use internet search as a substitute for a small direct REDmod/game-file inspection when the installed game can answer the question more authoritatively.

Community examples can still be useful for discovering a candidate seam or technique, but the supported installed-game evidence must confirm the actual contract before Biology treats it as foundational.

## Two different tracked snapshots

Do not conflate these.

### Current observed installation

The root of:

```text
reference\cyberpunk\
```

contains GitHub-safe metadata generated by `tools/Refresh-LocalGameReference.ps1`, including environment, filesystem, archive, framework, installed-script, and compatibility information.

This describes **whatever is currently installed** when the refresh runs. It may be vanilla, Biology-installed, or another intentional local state. Git history provides the running archive of these snapshots.

Refresh only from an active cprealpass checkout:

```powershell
pwsh ./tools/Refresh-LocalGameReference.ps1 `
  -GamePath 'C:\Games\Steam\steamapps\common\Cyberpunk 2077'
```

When a meaningful current state should be sent to GitHub for remote agents/history, use the repository-owned publishing tool documented in `docs/LOCAL-OPERATOR-COMMANDS.md`. It publishes derived metadata only and does not upload proprietary game files.

### Known-clean vanilla baseline

The directory:

```text
reference\cyberpunk\vanilla-baseline\
```

is reserved for the deliberately clean vanilla reference state used by attended testing.

A populated baseline contains only derived metadata such as:

- relative paths;
- file sizes;
- SHA-256 hashes;
- game/executable version;
- capture timestamp and aggregate counts.

It contains **no Cyberpunk file content**. The baseline is used to prove that a reused game directory has no unexplained extra, missing, or modified files before an iteration test.

Use the canonical bootstrap/capture/compare/reset commands in `docs/LOCAL-OPERATOR-COMMANDS.md`; do not assume a permanent repository directory.

## What remote agents can request

Good reasons for a targeted local probe include:

- exact vanilla resource paths;
- native class/function/event/stat/status-effect/TweakDB record existence;
- direct REDmod script-source evidence for controller/lifecycle ownership;
- consumable/inventory/equipment/controller/state-machine behavior;
- installed framework versions;
- relevant game logs;
- narrow archive extraction of one needed resource family;
- confirmation that an online claim still applies to the supported build.

Local evidence requests must follow `docs/LOCAL-OPERATOR-COMMANDS.md`: self-bootstrap the repo when needed, remain read-only whenever practical, and generate a plain-text `.txt` evidence report for the user to attach back to ChatGPT instead of pasting a long terminal transcript.

Once a probe establishes a durable fact, preserve the conclusion in code/docs/tests/metadata so future agents do not rediscover it.

## Archive/resource inspection

REDmod's installed script tree should be used before archive extraction when the question is purely about script behavior.

If an answer instead depends on an archive-backed resource, INK widget, texture, mesh, or other packaged asset, use a narrow supported extractor such as WolvenKit/REDmod tooling as appropriate. Extract only the smallest relevant resource family into a disposable local workspace; do not bulk-extract the game by default.

Any extracted proprietary content remains local and gitignored. Only redistribution-safe conclusions, paths, hashes, symbol names, or project-created fixtures belong in Git.

## What belongs in Git

Appropriate derived additions include:

- technical conclusions;
- vanilla resource/symbol/record names;
- narrow native signatures needed by Biology adapters;
- small indexes and hashes;
- compatibility probes/scripts;
- versioned environment metadata;
- tests/fixtures created by this project.

Do **not** commit:

- vanilla `.archive` containers;
- game executables or DLLs;
- bulk REDmod-decompiled game scripts;
- textures, meshes, audio, videos, or other game assets;
- bulk extracted/decompiled game content.

The repository should remain independently redistributable as Biology source, documentation, tooling, and legally appropriate metadata — not as a mirror of Cyberpunk 2077.

## Design consequence

If a feature appears to require a new Biology mechanism, first investigate whether vanilla already exposes an appropriate authority/lifecycle/state source. The preferred shape is:

```text
stable Biology simulation core
        |
        v
small semantic compatibility adapter
        |
        v
native Cyberpunk / official REDmod contract
```

Version-sensitive details belong in the adapter, not throughout the model.

## Safety rule

Inspection commands are read-only by default. Commands that modify/delete/rename/repack installed game files require a separately justified task and explicit user awareness.

The attended-test cleanup/install tools are a special case documented in `docs/CLEAN-ROOM-TESTING.md`; they act only on proven package-owned files and fail closed if ownership/baseline evidence is insufficient.
