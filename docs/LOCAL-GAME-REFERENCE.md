# Local Cyberpunk Game Reference

## Purpose

Remote GitHub agents do not have direct filesystem access to the user's installed copy of Cyberpunk 2077. The repository therefore maintains **GitHub-safe derived metadata** about the real local game and can ask the user to run targeted read-only PowerShell/CMD/WolvenKit probes when that evidence matters.

This is part of RealPass's patch-resilience strategy: foundational integrations should be based on the actual supported game build and stable semantic contracts rather than assumptions copied from old guides or unrelated mods.

## Two different tracked snapshots

Do not conflate these.

### Current observed installation

The root of:

```text
reference\cyberpunk\
```

contains metadata generated by `tools/Refresh-LocalGameReference.ps1`, including:

- `environment.json`
- `filesystem-index.csv`
- `archives.csv`
- `frameworks.json`
- `red4ext-plugins.json`
- `installed-scripts.csv`
- `archive-payloads.csv`

This describes **whatever is currently installed** when the refresh runs. It may be vanilla, RealPass-installed, or another intentional local state. Git history provides the running archive of these snapshots.

Refresh only in the local checkout with:

```powershell
pwsh ./tools/Refresh-LocalGameReference.ps1
```

When a meaningful current state should be sent to GitHub for remote agents/history, use:

```powershell
pwsh ./tools/Publish-LocalGameReferenceSnapshot.ps1
```

That creates/pushes a dedicated `local-game-snapshot-*` branch containing only `reference/cyberpunk/` metadata. It does not upload game files.

### Known-clean vanilla baseline

The directory:

```text
reference\cyberpunk\vanilla-baseline\
```

is reserved for the deliberately clean vanilla reference state used by attended testing.

A populated baseline contains only derived metadata:

- relative paths;
- file sizes;
- SHA-256 hashes;
- game/executable version;
- capture timestamp and aggregate counts.

It contains **no Cyberpunk file content**. The baseline is used to prove that a reused game directory has no unexplained extra, missing or modified files before an iteration test.

Capture it only from a deliberately clean milestone installation:

```powershell
Set-Location 'C:\Games\CyberpunkRealism'
pwsh ./tools/Capture-VanillaGameBaseline.ps1 -Publish
```

The `-Publish` path creates and pushes a dedicated `local-vanilla-baseline-*` Git branch containing only `reference/cyberpunk/` metadata. A remote agent can review/merge that branch without receiving proprietary game data.

To compare the current game directory against the recorded clean state:

```powershell
pwsh ./tools/Compare-GameToVanillaBaseline.ps1
```

For ordinary RealPass iteration after a prior package test:

```powershell
pwsh ./tools/Reset-RealPassIteration.ps1
```

That reset removes only files proven to belong to the immediately prior RealPass package and absent from the vanilla baseline, then requires the strict baseline comparison to pass. If it cannot prove safety, it stops and requires a milestone clean-room reset.

See `docs/CLEAN-ROOM-TESTING.md` for the canonical attended-test policy.

## Evidence priority

When a question is about what Cyberpunk itself contains, exposes, names, calls, stores, or does, use this order:

1. tracked RealPass code/docs/tests and the generated `reference/cyberpunk/` metadata;
2. targeted direct inspection of the user's installed game;
3. official game/framework/tool documentation and release notes;
4. community guides/examples as secondary evidence.

Do not use internet search as a substitute for a small direct inspection when the installed game can answer the question more authoritatively.

## Local layout

Current Windows layout:

```text
C:\Games\CyberpunkRealism
├─ game-reference\
│  ├─ live\        -> junction to installed Cyberpunk 2077
│  ├─ index\       -> generated local indexes
│  ├─ extracted\   -> safe workspace for selective extraction
│  └─ manifest.json
├─ reference\cyberpunk\
│  └─ vanilla-baseline\   -> tracked derived clean-state metadata
└─ ...tracked RealPass repository files...
```

The real game installation is:

```text
C:\Games\Steam\steamapps\common\Cyberpunk 2077
```

`game-reference\live` reaches the actual installation and must be treated as read-only during investigation.

The entire local `game-reference/` tree remains gitignored. Only redistribution-safe derived metadata under tracked `reference/cyberpunk/` belongs in Git.

## What remote agents can request

Good reasons for a targeted local probe include:

- exact vanilla resource paths;
- native class/function/event/stat/status-effect/TweakDB record existence;
- consumable/inventory/equipment/controller/state-machine behavior;
- installed framework versions;
- relevant game logs;
- narrow archive extraction of one needed resource family;
- confirmation that an online claim still applies to the supported build.

A request should normally provide one copy/paste-ready command using the known absolute paths. Prefer small filtered outputs, hashes, names, record IDs, metadata, or narrowly scoped text over proprietary file contents.

Once a probe establishes a durable fact, preserve the conclusion in code/docs/tests/metadata so future agents do not rediscover it.

## WolvenKit

If archive-level inspection is needed, first verify availability:

```powershell
wolvenkit.cli --help
```

If available, use selective extraction into:

```text
C:\Games\CyberpunkRealism\game-reference\extracted
```

Do not bulk-extract the game by default.

## What belongs in Git

Appropriate derived additions include:

- technical conclusions;
- vanilla resource/symbol/record names;
- small indexes and hashes;
- compatibility probes/scripts;
- versioned environment metadata;
- tests/fixtures created by this project.

Do **not** commit:

- vanilla `.archive` containers;
- game executables or DLLs;
- textures, meshes, audio, videos, or other game assets;
- bulk decompiled/extracted game content;
- anything under the gitignored `game-reference/` tree.

The repository should remain independently redistributable as RealPass source, documentation, tooling and legally appropriate metadata — not as a mirror of Cyberpunk 2077.

## Design consequence

If a feature appears to require a new RealPass mechanism, first investigate whether vanilla already exposes an appropriate authority/lifecycle/state source. The preferred shape is:

```text
stable RealPass simulation core
        |
        v
small semantic adapter
        |
        v
vanilla Cyberpunk contract
```

Version-sensitive details belong in the adapter, not throughout the model.

## Safety rule

Inspection commands are read-only by default. Commands that modify/delete/rename/repack installed game files require a separately justified task and explicit user awareness.

The attended-test cleanup tools are a special case documented in `docs/CLEAN-ROOM-TESTING.md`: they act only on manifest-owned RealPass test files and fail closed if ownership/baseline evidence is insufficient.
