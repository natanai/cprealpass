# realpass roadmap

1. **Single-mod consolidation.** Inventory every currently imported/source-mod feature, identify the one authority for each physical phenomenon, remove out-of-scope inherited systems, and route the retained functionality through one realpass configuration/settings structure. Every major gameplay module must be independently toggleable without requiring unrelated modules.
2. **Presentation and body acceptance.** Verify realpass naming, unclipped needs, E3/modern scanner transitions, food/drink absorption, exertion, wait/sleep, bathroom/washing and save/reload in one combined session. Presentation should support the simulation without replacing useful modern game functions.
3. **Timing and calibration.** Measure the native game clock, menu/lifecycle boundaries, scripted jumps and long skips. Tune daily resource use, fatigue, digestion/elimination and recovery against applied in-game behavior rather than arbitrary survival pressure.
4. **Realistic combat and injury activation.** Integrate projectile/ammunition behavior, hit regions, physical armor coverage, cybernetic structure, tissue injury, blood loss, impairment, stabilization, treatment and recovery as one pipeline. Remove health-sponge and generic-clothing-armor behavior where the engine permits, while preserving bosses, authored immunity and quest-critical logic.
5. **Gameplay compatibility and release structure.** Validate player/NPC symmetry, nonlethal outcomes, performance and Phantom Liberty sequences. Finish reproducible acquisition/bootstrap, permitted packaging, updates and rollback so the distributed result behaves as one mod rather than a required mod stack.

## Scope exclusions

Do not spend release work on weather control, economy rebalancing, arbitrary scarcity, added random encounters, travel restrictions, summon currencies, or an added outfit/transmog system. Clothing remains clothing; armor protection belongs to actual protective equipment. Source-mod features that fall outside the realism model should be omitted, not preserved merely because they can be toggled.

Implemented models and compiled scripts are progress, but native behavior remains an acceptance requirement. Prefer large, useful playtest batches over repeated individual checks.
