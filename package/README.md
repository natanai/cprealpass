# realpass — development package 0.1.0-dev.19

This redistribution-safe **development/source artifact** contains the project-original runtime policy model, the passive realpass-owned player settings surface, nineteen simulation/data modules and the authored stock-protection recipe. It exists for offline model review, CI packaging and source handoff. It is deliberately not the finished drag-and-drop gameplay mod.

The runtime policy model and `RealpassSettings.reds` are the current code-level consolidation step toward one realpass settings authority. Twenty player-facing Boolean preferences are grouped under realpass in Mod Settings; the development diagnostics flag remains out of the ordinary player menu. The settings system only records player intent and maps it into policy flags whose native acceptance booleans remain closed. Changing a setting in this artifact cannot activate the staged body/combat bridges by itself. The current native adapters are not yet wired to consume those policy flags.

The package also includes body resources, ordered intake, servings, clock policy, meter migration, sleep accounting, forecasts, physical impacts, contact selection, projectile profiles, localized injuries, field-care plans, wound conversion, a stock equipment resolver, regional armor-wear arithmetic, injury-to-ability projection and NPC progression through the shared body solver.

It does not contain the native gameplay adapters, Dark Future integration patches or UI bridges and **does not activate gameplay**. The separately installed quiet/broad local integration profiles are different local builds. Keep this archive separate; do not manually extract it over an installed test profile.

The stock resolver covers 294 exact game item identifiers using five original profiles. It includes 71 shirts, 117 trousers, 30 intrinsic-armored vests, 11 current subdermal armor tiers and 65 optical implants. Unknown records remain unresolved. The recipe uses stock identifiers and original coefficients; no game assets or upstream implementation bodies are included. Its values are provisional gameplay assumptions, not measured armor/material ratings. Coarse regional coverage still needs visual and gameplay validation. The native integration supports explicit overrides, but that bridge is outside this archive.

Script prerequisites for compiling all source modules in-game are redscript 0.5.31 and Mod Settings 0.2.21 on Cyberpunk 2077 2.31. Mod Settings is needed only by `RealpassSettings.reds`; the engine-independent models and runtime-policy model do not depend on it. The manifest records payload paths and SHA-256 hashes. Arithmetic, fixture checks and compilation do not prove engine serialization, live item availability, timing, rendering, mission compatibility or performance.

Adapted third-party components must retain applicable author, license and modification notices. Project E3 HUD remains an external/reference dependency in local presentation work and is not contained here. This archive contains no third-party binaries or assets and starts no process, watcher or logger.

Armor wear uses absorbed projectile energy and stores normalized wear independently for six regions. The pure model includes acceptance rules for acknowledged zero-health-damage armor stops. Item-instance/NPC persistence, equipment sampling and native commit adapters are implemented in the separate staged profile; they are not in this archive and remain unverified in game. Registry capacity, malformed state, replay and repeated-impact checks do not prove engine serialization, inventory identity or performance.

Impairment projects regional function and blood deficit into bounded movement, stamina, reload, recoil and accuracy factors. Bone support can improve function without healing the underlying injury. Coefficients are provisional gameplay tuning. Native modifier ownership, scene/suspend cleanup, weapon changes and NPC registration are implemented and fixture-tested in the separate staged profile, not this archive. Native movement/AI behavior and save/load cleanup remain unverified. This module does not implement blood-loss death or handedness-specific handling. NPC body progression is now supplied by the separate original NPCBodyModel module.

NPCBodyModel reuses the same bounded minute solver as V, retaining body resources, pending time and one injury owner. The native schema migration and shared-clock registry connection are in the staged profile, outside this archive. Model/fixture checks cover progression, conservation and reconstruction; AI eating, drinking, sleep, offscreen continuity, actual native saves and performance are not verified or complete. Initial NPC resource reserves are provisional; no historical metabolism is invented during migration. V's sleep never counts as NPC sleep automatically.

FieldCareActionModel adds transient queued/active/completion timing for dressing and limb support. The separate staged native adapter uses bounded in-game action callbacks, cancellation and completion-only item debit; those adapters are not included in this pure-module archive. No external process or diagnostic logger is added. Treatment animations, engine callback behavior and input/notification usability remain unverified.

BloodLossModel tracks a bounded transient delivery cursor over the shared injury model's cumulative severe-blood-loss exposure. It prevents replay after restoration/protection, duplicate in-flight events and unlimited catch-up bursts. The separately staged native profile translates eligible demand into native damage events; those adapters are excluded here and are not installed. Human boss/MaxTac weaponless delivery now has a capped native adapter with offline evidence; native boss phases, kill attribution, final death behavior, skip-time consequences and damage cadence remain activation gates. These are provisional gameplay coefficients, not calibrated physiology.
